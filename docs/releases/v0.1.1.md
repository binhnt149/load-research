# Load Research Desktop 0.1.1

Bản **thử nghiệm** sửa lỗi sao lưu trên Windows và bổ sung đóng gói native cho macOS Apple Silicon/Windows x64. Phương pháp tính vẫn là `class-profile-v1`; không thay schema hoặc chuyển đổi dữ liệu dự án.

## Thay đổi

- Đóng kết nối SQLite đích trước khi đổi tên hoặc dọn thư mục sao lưu, kể cả khi công bố backup lỗi.
- Đóng gói đủ FFT/linalg và backend SVG được nhập động; dùng Clang-cl để biên dịch SciPy trên Windows.
- GitHub Actions chạy toàn bộ quality gates, native demo và xuất XLSX/PNG/SVG trước khi tạo pre-release.

## Tải và chạy thử

Tệp xuất hiện tại [GitHub Release v0.1.1](https://github.com/binhnt149/load-research/releases/tag/v0.1.1) sau khi workflow tag đạt mọi gate. Tải `SHA256SUMS` cùng các tệp cần dùng và đối chiếu SHA-256 trước khi mở:

| Nền tảng | Tệp và cách dùng |
|---|---|
| macOS Apple Silicon arm64 | `LoadResearch-0.1.1-macos-arm64.dmg`: mở DMG, kéo `LoadResearch.app` vào Applications |
| Windows x64 | `LoadResearch-0.1.1-windows-x64.zip`: giải nén, chạy `LoadResearch.dist/launcher.exe`, giữ nguyên cả thư mục |
| Python 3.12 | `load_research-0.1.1-py3-none-any.whl`: cài trong venv theo README cùng `requirements.lock` |

macOS dùng `shasum -a 256 <tệp>`; Windows PowerShell dùng `Get-FileHash <tệp> -Algorithm SHA256`. Chỉ khi đã tải đủ mọi asset mới dùng `shasum -a 256 -c SHA256SUMS` để kiểm tra toàn bộ manifest. Hai báo cáo `native-smoke-*.json` và lock công cụ build cũng được phát hành để truy vết.

Các gói native chưa ký Developer ID/notarize hoặc Authenticode. macOS chỉ có arm64; Windows là bản portable. Không yêu cầu cài Python cho gói native; việc chạy trên máy sạch vẫn cần nghiệm thu E02.

## Kiểm thử và giới hạn

Lượt tag phải vượt qua Ruff, mypy, toàn bộ pytest và dependency audit trên hai OS; cả hai native phải chạy demo và xuất đủ XLSX/PNG/SVG. Publisher chỉ lấy artifact từ chính lượt chạy tag, kiểm tra đủ tệp/báo cáo smoke rồi tạo checksum. [Bằng chứng phát hành](../verification/release-0.1.1.md) ghi kết quả thực và các bước còn chờ; không suy diễn native CLI smoke thành UAT giao diện.

Trước thử với dữ liệu thật, tạo bản sao lưu dự án. Kiểm tra tạo/mở dự án, nhập demo, chạy/huỷ/chạy lại, chuyển 24/48 và kW/kWh, xem biểu đồ chung/thành phần, xuất và mở bản sao lưu. E01 (tệp CMIS/MDMS thực), E02 (GUI/worker trên máy sạch), E03 (7.000 khách hàng × 12 tháng/UAT) vẫn cần nghiệm thu riêng.

Nếu gặp lỗi tính toán hoặc toàn vẹn dữ liệu, đóng ứng dụng, giữ nguồn/dự án lỗi để đối chiếu và mở bản sao lưu ở thư mục riêng. Giữ tag và asset đã phát hành để truy vết; bản sửa tiếp theo dùng phiên bản mới. Nhật ký lưu cục bộ, không có telemetry.
